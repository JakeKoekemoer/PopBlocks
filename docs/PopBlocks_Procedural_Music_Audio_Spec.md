# PopBlocks: The Shattered Spectrum
## Procedural Music & Audio System — Developer Specification

**Document status:** Proposed implementation specification  
**Target:** Existing PopBlocks codebase, C# / .NET MAUI, Visual Studio  
**Design goal:** An original, emotionally expressive soundtrack and responsive sound effects generated or controlled by code, with no ads, analytics, tracking, streaming, or runtime network dependency.

---

## 1. Creative vision

PopBlocks should sound like a small, magical world that is slowly learning to shine again.

The music begins intimate and curious. It should support a relaxing puzzle game without becoming sleepy or repetitive. Each region has a distinct musical identity, but all eight regions belong to the same world. Their melodies should feel related, and the final region should bring those musical ideas together.

The emotional centre of the soundtrack is the story's central idea: **the same colours can form new connections**. The world is not simply returned to its old state; it learns to become something new.

The audio should feel:
- **Cosy and inviting** during ordinary play.
- **Curious and magical** during exploration.
- **Satisfying and rhythmic** when colour groups burst and chains build.
- **Quietly emotional** during story revelations.
- **Warm, expansive and earned** during restoration and the finale.

Do not imitate any specific game's soundtrack, melody, arrangement, sound effects, or distinctive audio identity. Use the references in this document only as broad emotional descriptors. All melodies and sound designs must be original.

## 2. Technical direction

### 2.1 Recommended approach: hybrid procedural audio

Build a small, self-contained audio subsystem in C#.

Use code for:
1. Musical rules, note selection, chord progressions, rhythms and variations.
2. Procedural synthesis of simple tones and instrument-like sounds.
3. Gameplay sound effects such as colour pops, combo accents, crystal chimes, restoration sweeps and UI feedback.
4. Adaptive decisions: which region theme is active, when a layer enters, and how music responds to gameplay.

Use **rendered, bundled audio files only where they provide a clear benefit** (for example, a complex ambience texture or a particularly CPU-expensive pad). The first prototype should not depend on externally sourced music or an online service.

### 2.2 Important implementation distinction

“Music generated by code” can mean either generating a composition or generating its sound. Keep these separate:

- **Composition:** creates a sequence of musical events.
- **Synthesis:** converts those events into audio samples.
- **Playback/output:** delivers audio to the device at a stable sample rate.
- **Direction:** selects the profile and responds to game events.

The composer must not write audio directly to the device. The game loop must not generate samples. A dedicated audio worker/output callback should process audio in bounded time and avoid blocking the UI thread.

### 2.3 Playback backend decision

Before choosing a package, audit the current repository and target platforms. Prefer the smallest stable option that supports the actual target platforms and has a reviewable licence and source.

**Initial preference:** use platform-native playback/output behind an internal interface, or a minimal maintained audio library after a dependency audit. Do not assume any package is tracking-free solely because it is open source.

The implementation must:
- Require no network access for audio.
- Include no telemetry, analytics, ad SDK, attribution SDK, or crash-reporting SDK as part of the audio subsystem.
- Avoid dynamic downloads or streamed assets.
- Use only bundled/generated assets and local settings.
- Have its licence, transitive dependencies, platform permissions and network behaviour reviewed before approval.
- Avoid introducing a large game engine solely for music playback.

Keep the output backend replaceable. Do not expose package-specific types outside the audio layer.

### 2.4 First implementation milestone

Start with a **short, procedurally generated audio prototype**, not all eight complete soundtracks.

The prototype must prove:
1. A note sequence can be composed from musical rules.
2. The synthesiser can render at least three timbres.
3. Playback is stable on the primary target device.
4. Music can loop without an obvious gap or click.
5. A game event can trigger a sound effect without restarting the music.
6. Muting music does not mute sound effects, and vice versa.
7. The audio subsystem works fully offline.

After that, tune the sound and expand the content.

### 3.1 `MusicDirector`

Responsibilities:
- Enter and leave a region.
- Select the correct musical profile and region state.
- Start, pause, resume, and transition music.
- Respond to level, story, combo and restoration events.
- Ask for changes on musical boundaries when possible.
- Keep music state independent from sound-effect state.

Suggested interface:

```csharp
public interface IMusicDirector
{
    Task EnterRegionAsync(
        RegionId region,
        RegionRestorationState state,
        CancellationToken cancellationToken = default);

    Task SetRestorationStateAsync(
        RegionRestorationState state,
        CancellationToken cancellationToken = default);

    void SetGameplayIntensity(float intensity);
    void TriggerStoryCue(StoryAudioCue cue);
    void Pause();
    void Resume();
    void Stop();
}
```

Do not make every short sound effect an `await`-heavy operation. Sound effects should be triggerable with low latency through a separate interface.

### 3.2 `MusicComposer`

Responsibilities:
- Generate phrase structures, note events and controlled variations.
- Respect a profile's scale, register, tempo, rhythm and harmonic rules.
- Produce repeatable output for a known seed.
- Avoid random note selection that creates dissonant or directionless music.
- Keep melody, harmony, bass and percussion in separate tracks/layers.

### 3.3 `MusicSequencer`

Responsibilities:
- Schedule notes against a musical clock.
- Support beat, bar, phrase and loop boundaries.
- Schedule quantised changes without blocking the game thread.
- Handle tempo and time signatures.
- Avoid restarting the whole soundtrack on each gameplay event.

### 3.4 `MusicSynthesizer`

Responsibilities:
- Render floating-point audio samples at the output sample rate.
- Support overlapping voices and smooth note envelopes.
- Offer a small, curated set of original timbres.
- Prevent clicks when starting/stopping notes.
- Avoid allocating memory or locking heavily inside a real-time audio callback.
- Clamp output and avoid clipping.

### 3.5 `AudioMixer`

Responsibilities:
- Mix music, ambience, and sound effects into separate buses.
- Apply master, music, ambience and SFX volume controls.
- Provide smooth fades and duck music under important dialogue.
- Avoid one loud effect clipping the output.

### 3.6 `AudioEventRouter`

Responsibilities:
- Translate existing game events into audio events.
- Coalesce repeated events and prevent excessive sound spam.
- Keep audio code from becoming coupled to board rendering or puzzle rules.

Example event mapping:
- `ColourGroupCleared` → colour pop, selected by colour/tier.
- `ChainIncreased` → additional musical accent.
- `LevelCompleted` → completion flourish.
- `RegionRestored` → restoration sweep and music-state transition.
- `MemoryCrystalActivated` → crystal motif.
- `WardenRevealed` → Warden motif.
- `PrismHeartRestored` → finale sequence.

Use the existing event system if the repository already has one.

## 4. Musical language and original Spectrum motif

### 4.1 Palette of sounds

The sound system should combine simple electronic tones with warmer, instrument-like procedural sounds.

| Instrument patch | Synthesis direction | Best use |
|---|---|---|
| `PureTone` | Sine wave with a short envelope | Precise UI feedback, subtle puzzle accents |
| `SpectrumBell` | Sine/triangle partials with fast attack and decaying upper harmonics | Crystal chimes, shard discoveries |
| `SoftPluck` | Plucked-string-like decay using a simple exciter/filter or shaped harmonics | Main melody, arpeggios |
| `WoodenMarimba` | Short, rounded, inharmonic or near-harmonic partials | Playful patterns, Verdant Wilds |
| `WarmPad` | Several quiet detuned/slowly moving partials with slow attack/release | Harmony, emotional scenes |
| `SoftBass` | Low sine/triangle with gentle transient | Harmonic foundation, machine pulse |
| `AirNoise` | Filtered noise with a shaped envelope | Wind, breath, sweep and soft impacts |
| `ClockPulse` | Short tonal/noise tick | Clockwork Wastes and restrained rhythm |

Start with three or four patches. Add complexity only when the prototype demonstrates that it improves the result. No external sample pack is required.

### 4.2 Musical identity

Create a short **five-note Spectrum motif** that can be recognised even when played slowly, in fragments, or on different instruments. Its final pitch sequence must be original and approved by listening tests; do not derive it from an existing game's soundtrack.

Represent it as note intervals relative to a root, rather than hardcoding one key. This allows transposition for each region.

The motif has four narrative treatments:
1. **Faded:** incomplete phrases, longer gaps, soft timbre.
2. **Remembered:** notes emerge as fragments, often with echoes.
3. **Connected:** phrases overlap or answer each other.
4. **Resolved:** all five notes resolve into a warm, complete phrase.

The motif is a musical thread, not a sound that should be forced into every effect.

### 4.3 Harmony and rhythm

- Use consonant, accessible harmony for the default puzzle loop.
- Use occasional suspended notes or unresolved chords for mystery, not constant dissonance.
- Prefer short phrases that can loop naturally.
- Make rhythm expressive but restrained. The puzzle should remain the focus.
- Use silence intentionally; not every beat needs a note.
- Support deterministic seeds so generated phrases can be reproduced during testing.
- Keep regional themes recognisably different through timbre, tempo, register, rhythm and arrangement—not merely by changing pitch.

## 5. Region soundtrack and restoration direction

Each region has a **Faded / Unrestored** state and a **Restored** state. The restored state should feel like the same musical idea learning to breathe, not an unrelated replacement song.

For the first release, implement one short looping theme per state only where it is needed. Do not require sixteen fully separate compositions from the outset. Reuse phrase material, instrument patches and motifs.

### Region 1 — Forgotten Garden (levels 1–25)

**Faded theme: “Where the Flowers Slept”**
- Mood: tender, curious, slightly lonely, never frightening.
- Tempo: approximately 68–76 BPM.
- Timbres: soft pluck, sparse bell, quiet sine foundation, optional faint air-noise swell.
- Rhythm: short phrases with generous pauses.
- Composition: a small rising phrase that stops just before it feels complete; occasional single high notes like distant fireflies.
- Mix: intimate, light, low density. Keep the melody clearly audible.

**Restored theme: “A Thousand Little Lights”**
- Reuse the central melody, complete its final phrase and introduce warmer harmony.
- Add gentle marimba-like notes and soft pad support.
- Increase rhythmic continuity slightly, but do not turn it into a fast or sugary jingle.
- Add a few high notes that answer the melody, suggesting lights appearing across the garden.

**Ambient layer:** quiet wind, distant leaf rustle, occasional soft firefly/chime. Ambience must not become a continuous hiss.

**Restoration cue:** a low-to-high warm sweep, three small bell notes, then the final note of the Spectrum motif.

### Region 2 — Crystal Caves (levels 26–50)

**Faded theme: “Echoes Without Answers”**
- Mood: mysterious, spacious, beautiful, not horror.
- Tempo: approximately 62–72 BPM.
- Timbres: glassy `SpectrumBell`, soft pluck, long but controlled echo/reverb if available.
- Rhythm: sparse and spacious; notes answer each other after a pause.
- Composition: use the Spectrum motif in fragments, as though the caves remember only part of it.

**Restored theme: “The Crystals Remember”**
- Build repeating, interlocking patterns from the same notes.
- Use bright upper notes and a gentle lower pulse.
- Let echoes overlap in a controlled way; avoid a cluttered, high-pitched wash.

**Ambient layer:** isolated crystal twinkles and subtle low cave air. Twinkles should be infrequent and randomised within safe limits.

**Shard discovery:** a distinctive three-part chime—soft low note, bright middle note, high resolving note—with a very short tail.

### Region 3 — Verdant Wilds (levels 51–75)

**Faded theme: “Roots of Silence”**
- Mood: earthy, patient, a little wistful.
- Tempo: approximately 72–82 BPM.
- Timbres: rounded marimba, soft pluck, quiet low pad.
- Rhythm: slow, unevenly spaced pulses that feel organic rather than mechanical.
- Composition: descending fragments and gentle pauses, with the motif buried in the middle register.

**Restored theme: “Everything Grows Together”**
- Introduce interlocking marimba/pluck phrases that respond to each other.
- Add a warm bass pulse and a few light high notes.
- Rhythms should feel cooperative, like separate parts growing together.

**Ambient layer:** very quiet leaf movement, soft insect/bird-like abstract tones. Avoid realistic loud animal calls that could become irritating.

**Restoration cue:** soft wooden taps grow into a short rising arpeggio, then a warm chord.

### Region 4 — Sunken City (levels 76–100)

**Faded theme: “Beneath the Quiet”**
- Mood: reflective, submerged, beautiful and melancholy.
- Tempo: approximately 58–68 BPM.
- Timbres: soft pad, rounded pluck, bell notes with a softened attack.
- Rhythm: flowing phrases with long spaces.
- Composition: downward motion followed by a note that hangs unresolved; low density to convey an abandoned place.

**Restored theme: “The City Remembers”**
- Reinterpret the same downward phrase as a flowing arpeggio.
- Add gentle harmony and brighter upper-register notes.
- Use slow, breathing dynamics rather than dramatic crescendos.

**Ambient layer:** very subtle bubbles and watery resonances. Keep transient sounds sparse and low in the mix.

**Memory cue:** a quiet, slightly softened version of the Spectrum motif followed by a gentle ripple-like descending tone.

### Region 5 — Clockwork Wastes (levels 101–125)

**Faded theme: “A Machine Waiting”**
- Mood: curious, lonely, slightly off-kilter.
- Tempo: approximately 76–88 BPM, with the pulse implied rather than aggressively stated.
- Timbres: `ClockPulse`, short marimba, dry pluck, low sine pulse.
- Rhythm: occasional skipped ticks and incomplete repeating patterns.
- Composition: a repeating motif that almost locks into place but leaves one beat empty.

**Restored theme: “A Different Kind of Order”**
- Make the pulse steady and satisfying.
- Layer two simple patterns that interlock without competing.
- Add rounded low notes and small metallic accents; avoid harsh industrial noise.

**Ambient layer:** quiet ticks, distant mechanical movement, occasional soft steam release. Random ambience must not obscure the musical beat.

**Machine activation cue:** three ticks that accelerate gently into a resonant chord. Avoid an alarm-like sound.

### Region 6 — Frozen Expanse (levels 126–150)

**Faded theme: “The Memory Beneath the Ice”**
- Mood: still, fragile, emotionally distant.
- Tempo: approximately 54–64 BPM.
- Timbres: isolated bell, soft pad, sparse low pluck.
- Rhythm: long pauses and slow, delicate notes.
- Composition: the Spectrum motif appears in fragments with missing notes; silence should be a deliberate part of the phrase.

**Restored theme: “When Winter Lets Go”**
- Keep the restrained tempo, but soften the harmony and connect the previously separated notes.
- Add a gentle supporting pad and occasional warm pluck.
- The change should feel like thawing, not a sudden sunny celebration.

**Ambient layer:** very soft wind, occasional tiny ice glint. Do not use continuous high-frequency wind noise.

**Restoration cue:** a delicate high note descends into a warmer chord, followed by a faint shimmer.

### Region 7 — Shattered Citadel (levels 151–175)

**Faded theme: “The Weight of the Guardian”**
- Mood: solemn, powerful, conflicted—not evil or horror-like.
- Tempo: approximately 66–76 BPM.
- Timbres: low pad, restrained bass, sparse bell and muted pulse.
- Rhythm: deliberate, with strong rests.
- Composition: introduce the Warden's original musical motif, built from the Spectrum motif but slowed, fragmented, and harmonically unresolved.

**Restored theme: “The Courage to Let Go”**
- Retain the Warden motif, but change the harmony around it.
- Gradually introduce warmer upper notes and a more open chord voicing.
- The musical transformation should convey acceptance and release rather than defeat.

**Ambient layer:** low wind and distant, subdued crystal resonance. Keep it nearly inaudible during dialogue.

**Warden reveal/confession:** strip the arrangement back to a low sustained tone and a few isolated motif notes. Leave space after important dialogue. Do not place a musical sting under every line.

### Region 8 — Heart of Spectrum (levels 176–200)

**Faded theme: “The Space Between Colours”**
- Mood: vast, suspended, emotionally charged, full of expectation.
- Tempo: approximately 64–76 BPM.
- Timbres: fragments of all prior regional patches, used sparingly.
- Rhythm: motifs appear separately and fail to complete their phrases.
- Composition: brief references to the garden, caves, wilds, city, clockwork, frozen expanse and Warden motifs. Do not stack everything at once.

**Restored theme: “Same Colours, New Connections”**
- Begin with the five-note Spectrum motif clearly stated.
- Bring regional motifs back in one at a time, harmonised to support one another.
- Combine soft pluck, crystal bell, marimba, warm pad, low bass and restrained rhythmic pulse.
- Build to a satisfying, emotionally warm resolution. It should feel earned and expansive, not bombastic or excessively loud.
- End with a short, recognisable phrase that can also serve as the game's credits/menu identity.

**Finale ambience:** subtle orbiting tones and small light-like chimes. Fade ambience beneath the main musical resolution.

**Prism Heart restoration cue:**
1. Briefly thin or pause the backing arrangement.
2. Reveal the five-note motif in its complete form.
3. Introduce the regional motifs one by one.
4. Resolve them into a warm, stable harmony.
5. Let the final note ring and decay naturally.
6. Transition into the restored Heart theme without an abrupt restart.

## 6. Global gameplay sound effects

All sound effects should be short, recognisable, non-fatiguing, and mixed below the music when appropriate. Avoid harsh high-frequency spikes, overly bass-heavy thumps, or long tails that clutter rapid play.

### 6.1 Colour burst sounds

Use a shared sound family so all colours feel part of the same game. Colour identity can be expressed through pitch/register and a subtle timbral variation, but don't rely on pitch alone for accessibility.

Suggested base patches:
- Cyan: clean, bright pluck.
- Magenta: slightly rounded bell.
- Amber: warm, woody note.
- Lime: soft, lively marimba-like note.
- Violet: glassy, airy chime.

These are initial mappings, not fixed laws. Keep loudness and perceived intensity reasonably consistent across colours.

**Single burst**
- Short attack, quick satisfying body, controlled decay.
- A simple two-note or single-note gesture; keep it short enough for rapid play.
- Typical duration: about 80–180 ms.

**Larger group**
- Slightly fuller chord or layered partials.
- Increase perceived richness more than raw volume.

**Consecutive bursts**
- Each subsequent burst adds a musically compatible note from the current scale.
- Use a bounded phrase so a long chain cannot climb endlessly in pitch.
- Reset or gently resolve the phrase when the chain ends.

**Large chain combo**
- A short ascending flourish with a resolving final note.
- Reserve the richest accent for meaningful combos; ordinary matches should remain understated.
- Never play a full celebratory sting on every small chain.

### 6.2 Landing and movement

- Block movement: optional very quiet, soft tick; disabled by default if it becomes repetitive.
- Rotation: a tiny rounded tonal tick, only if it improves tactile feedback.
- Piece landing: a short low-mid thump with a subtle tonal body.
- Avoid playing a loud sound for every frame or every repeated input.
- Add input debouncing/cooldowns where needed.

### 6.3 UI sounds

- Button tap: short soft click with a tiny tonal edge.
- Menu open: gentle two-note upward gesture.
- Menu close: matching downward gesture.
- Locked selection: muted, low-intensity double tap—never a harsh error buzz.
- Settings change: one quiet confirmation tone.
- Pause/resume: subtle paired cues; do not interrupt the music unnecessarily.

### 6.4 Level and progression cues

**Level start:** a brief welcoming phrase drawn from the active region motif.

**Level complete:** two or three notes that resolve clearly, with a duration around 0.5–1.5 seconds depending on context.

**New region unlocked:** the new region's motif appears in miniature, so the player hears its identity before entering.

**Memory crystal:** soft glassy chime, then a small echo. Dialogue must remain intelligible.

**Prism fragment acquired:** three notes that reveal the Spectrum motif a little more completely.

**Region restoration:** a layered sweep from low to high, small environmental accents, then a musical resolution. The sound effect should be synchronised with the visual restoration.

**Warden reveal:** one restrained low resonance followed by silence. Avoid a stereotypical villain sting.

**Final Heart restored:** use the full musical sequence defined in Region 8. Give it enough space to matter.

### 6.5 Failure and retry

- Near-failure tension should be subtle and optional. Prefer a quiet pulse or slightly altered accompaniment over an alarm.
- Failure cue: gentle, brief, and non-punitive. No harsh buzzer.
- Retry: return to the region's normal motif without a dramatic restart.
- Never use sound to pressure the player into continuing or spending currency.

## 7. Adaptive music rules

Use a few clearly defined musical states rather than continuously generating arbitrary changes.

### State A — Exploration / normal play
- Play the region's main looping phrase.
- Keep the arrangement sparse enough to coexist with puzzle effects.
- Use controlled variation at phrase boundaries.

### State B — Active chain
- Add a short rhythmic layer or additional melodic notes.
- Increase musical activity, not overall loudness.
- Fade back gracefully when the chain ends.

### State C — High combo
- Play a brief flourish or a musically aligned accent.
- Avoid restarting the background theme.
- Rate-limit repeated flourishes during very rapid chains.

### State D — Story dialogue
- Reduce rhythmic density.
- Duck the music slightly with a smooth envelope.
- Leave clear frequency and timing space for speech/text pacing.
- Restore the arrangement after the dialogue beat.

### State E — Restoration
- Schedule the transition at the next suitable beat or phrase boundary.
- Introduce the restored layers progressively.
- If the transition is event-driven and cannot wait for a bar, use a short crossfade rather than an abrupt restart.

### State F — Finale
- Use a scripted arrangement for reliable emotional timing.
- Ensure all motifs resolve musically.
- Do not let random procedural variation undermine the intended story climax.

## 8. Audio mixing, accessibility and player control

Provide separate settings for:
- Master volume.
- Music volume.
- Sound-effects volume.
- Ambience volume (optional).
- Mute music.
- Mute sound effects.

Requirements:
- Settings persist locally.
- Mute must be immediate.
- Volume changes use short smooth ramps to prevent clicks.
- Do not require headphones or stereo to understand gameplay.
- Keep important information available visually or through gameplay feedback.
- Avoid very high-frequency-only cues.
- Keep average music level and effect peaks balanced.
- Avoid clipping; apply conservative headroom and a final limiter only if justified.
- When the app is backgrounded, follow platform lifecycle rules and stop or pause playback appropriately.
- Respect device audio interruptions and route changes.
- Provide a reduced-audio option if feasible.

---

## 9. Performance and implementation requirements

- Target a stable output sample rate supported by the chosen backend, normally 44.1 kHz or 48 kHz.
- Use preallocated buffers in the audio callback.
- Do not allocate large objects, log excessively, or perform file I/O in the callback.
- Avoid locks that can block the real-time audio thread.
- Use a voice limit and sensible voice-stealing policy.
- Clamp the final mixed signal and monitor peak levels.
- Use smooth attack/release envelopes for all voices.
- Test on real Android devices, not only the Visual Studio emulator.
- Profile CPU, memory and battery consumption on a representative low-end device.
- If a platform's native output backend is unreliable, select a maintained library only after reviewing platform support, licence, dependencies and network behaviour.

---

## 10. Privacy, security and dependency requirements

The audio subsystem must:
- Work completely offline after installation.
- Make no network requests.
- Include no telemetry, analytics, ads, ad attribution, or external content loading.
- Store only necessary user preferences locally.
- Not request microphone access; PopBlocks does not need to record audio.
- Avoid unnecessary permissions.
- Bundle all required music definitions and sound assets with the app.
- Use an auditable dependency list and record the exact version and licence of any adopted package.
- Review transitive dependencies and inspect platform-specific manifests/permissions.
- Verify behaviour with source inspection and, where practical, network monitoring in a test build.

**Important:** no software can be guaranteed tracking-free merely by its name or licence. The project should treat privacy as a testable acceptance requirement.

## 11. Proposed configuration data

Use data-driven profiles to avoid duplicating composer code. The exact schema can evolve with the implementation.

```csharp
public sealed class RegionMusicProfile
{
    public RegionId Region { get; init; }
    public string FadedThemeId { get; init; } = string.Empty;
    public string RestoredThemeId { get; init; } = string.Empty;

    public int TempoBpm { get; init; }
    public int RootMidiNote { get; init; }
    public int[] ScaleIntervals { get; init; } = [];
    public int[] SpectrumMotifIntervals { get; init; } = [];

    public string MelodyPatch { get; init; } = "SoftPluck";
    public string HarmonyPatch { get; init; } = "WarmPad";
    public string AccentPatch { get; init; } = "SpectrumBell";

    public float BaseIntensity { get; init; } = 0.35f;
    public int VariationSeed { get; init; }
}
```

This is an illustrative data contract. Validate profiles at startup or in tests so invalid scales, tempos, note ranges or missing patch identifiers cannot crash playback.

The composer should be deterministic for a given profile/seed when deterministic output is requested. Runtime variation must remain constrained by the profile.

## 12. Suggested implementation phases

### Phase 1 — Audio proof of concept
- Inspect the existing repository and target platforms.
- Choose an output backend after dependency and privacy review.
- Implement a simple audio output interface and mixer.
- Synthesize a sine tone, bell, pluck and soft pad.
- Generate one 8–16 bar Forgotten Garden prototype.
- Add a short colour burst and chain accent.
- Confirm offline behaviour, stability and independent volume controls.

### Phase 2 — Music foundations
- Implement note events, scales, chords, phrase boundaries and deterministic seeds.
- Build the Spectrum motif.
- Add smooth looping and transition support.
- Implement the MusicDirector and event routing.
- Add basic music/SFX settings.

### Phase 3 — First playable region
- Complete the Forgotten Garden faded and restored states.
- Integrate colour bursts, chain combos, level completion and restoration.
- Test sound fatigue over a long play session.
- Tune levels and CPU use on real hardware.

### Phase 4 — Reusable regional profiles
- Add Crystal Caves, Verdant Wilds, Sunken City, Clockwork Wastes, Frozen Expanse, and Shattered Citadel.
- Reuse motifs and patches while keeping each region distinct.
- Implement Warden and memory crystal story cues.

### Phase 5 — Heart of Spectrum and finale
- Combine regional motifs.
- Script the Heart restoration sequence.
- Test the ending's timing against story visuals and dialogue.
- Make sure the finale is emotionally satisfying without being excessively loud.

### Phase 6 — Release hardening
- Test pause/resume, backgrounding, audio interruptions, mute and settings persistence.
- Run dependency, licence, permissions and network audits.
- Verify the app has no runtime audio network dependency.
- Profile performance and memory use.
- Confirm that the game remains fully playable with sound disabled.

## 13. Acceptance criteria

The audio system is ready for release when:
- [ ] All audio plays offline from bundled or generated content.
- [ ] No ads, analytics, telemetry or tracking components have been added to the audio subsystem.
- [ ] The chosen output backend and every dependency have been reviewed.
- [ ] A region can switch between faded and restored music states without an abrupt restart.
- [ ] The five-note Spectrum motif is recognisable across multiple regions.
- [ ] Every region has a distinct identity in rhythm, timbre, register or arrangement.
- [ ] Single pops are satisfying but not fatiguing during repeated play.
- [ ] Chain combos sound progressively more rewarding without becoming chaotic.
- [ ] Story dialogue and important visual moments are not obscured by audio.
- [ ] Music and sound effects have independent volume controls.
- [ ] Audio can be muted immediately.
- [ ] The audio thread does not block gameplay or cause audible glitches under load.
- [ ] Audio behaviour is tested on target devices.
- [ ] The final Heart sequence resolves the main musical motifs intentionally.
- [ ] The game remains fully playable with all audio disabled.

## 14. Final creative principle

The soundtrack should not constantly tell the player how to feel. It should give the world room to breathe.

A colour burst is a tiny spark. A chain is several sparks finding a rhythm. A restored region is a place remembering how to sing. The Warden's theme is not evil—it is the sound of someone carrying a burden for too long. And the final theme is not simply all the other themes playing louder; it is those themes discovering that they belong together.

The musical expression of the game's central line is:
